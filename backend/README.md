# ICAIH 2026 Backend Setup

## 1) Install packages
```bash
cd backend
npm install
```

## 2) Configure MySQL
Create a `.env` file based on `.env.example`:
```env
PORT=3000
DB_HOST=localhost
DB_PORT=3306
DB_USER=root
DB_PASSWORD=
DB_NAME=conference_db
```

## 3) Create database
Option A: run `database.sql` in MySQL.

Option B: just run the backend. It will create the required tables automatically after connecting to the database.

## 4) Start the backend
```bash
npm start
```

## Latest registration rules

- Registration IDs are generated in order as `ICAIH-2026001`, `ICAIH-2026002`, `ICAIH-2026003`, and so on.
- The sequence is protected using a MySQL transaction and row lock, so simultaneous submissions still receive separate IDs in order.
- `Payment Reference / UTR Number` is required for paid registrations in the registration form.
- User confirmation email is sent to the email address entered in the registration form.
- Admin notification email is sent to `ADMIN_EMAIL`, normally `info@mrtech.co.in`.

If emails are not received, check the backend terminal. The registration will still be saved, but the terminal will show the exact SMTP error, such as wrong password, blocked SMTP login, or incorrect host/port.


## Email sending setup for GoDaddy Professional Mail

If registration is saved but email is not sent, open `backend/.env` and add these values:

```env
SMTP_HOST=smtpout.secureserver.net
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=info@mrtech.co.in
SMTP_PASS=your_info_mail_password
MAIL_FROM=ICAIH 2026 <info@mrtech.co.in>
ADMIN_EMAIL=info@mrtech.co.in
```

Important:
1. Use the real password for `info@mrtech.co.in`.
2. Do not use the webmail inbox URL as SMTP host.
3. After changing `.env`, stop the backend with `Ctrl + C` and start it again using `npm start`.
4. If port 465 fails, try:

```env
SMTP_HOST=smtpout.secureserver.net
SMTP_PORT=587
SMTP_SECURE=false
```

The backend now shows the exact email failure reason in the registration message and prints the full SMTP error in the terminal.

After editing `.env`, restart backend:

```bash

```

## Manual UPI Payment Proof Flow

This project does not use a payment gateway. The full registration amount is paid directly to the linked UPI/bank account.

Flow:

1. User fills the registration form.
2. Website shows the selected fee and the static ICAIH UPI QR image.
3. User pays through Google Pay, PhonePe, Paytm, BHIM, or another UPI app.
4. User enters UTR / transaction ID.
5. User enters the UTR / transaction ID.
6. Registration is saved with `payment_status = pending-verification`.
7. Admin team manually verifies the UTR against the bank/UPI statement.

Important: Since there is no payment gateway, automatic payment verification is not possible. Manual admin verification is required.

For old databases, these columns are added automatically on backend start:

```sql
payment_status
payment_reference

```


For all three application forms, set `APPLICATION_ADMIN_EMAIL=divyav16.ai@gmail.com`. Uploaded competition, research paper, and award nomination files are attached automatically to this notification email.
